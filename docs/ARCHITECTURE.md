# Architecture

## Runtime flow

Browser
  -> FastAPI static frontend
  -> POST /api/chat
  -> language detection and query classification
  -> metadata scope selection (DarGlobal / Wasalt / both)
  -> FastEmbed multilingual query vector
  -> FAISS semantic candidates
  -> BM25 lexical candidates
  -> Reciprocal Rank Fusion
  -> deduplication and optional adjacent-chunk expansion
  -> bounded evidence context
  -> OpenRouter chat completion
  -> grounded answer + citations
  -> browser

## Offline build flow

Official websites/PDFs
  -> scraper
  -> normalized data/processed/documents.jsonl
  -> ingestion and chunking
  -> FastEmbed passage vectors
  -> FAISS index
  -> BM25 corpus/metadata
  -> SQLite source and chunk metadata
  -> index manifest
  -> Docker image

## Retrieval details

- Use stable chunk IDs.
- Retain source_id, company, category, title, URL, publication date, retrieval date, language, page number if PDF, and chunk position.
- Use model-specific query/document formatting exactly as documented by the selected FastEmbed model. Do not blindly apply E5 prefixes to a different model.
- Use normalized vectors and cosine-equivalent FAISS search.
- BM25 must support Arabic reasonably; normalize Arabic orthographic variants carefully without destroying original text. Preserve original text for generation.
- RRF score: sum 1 / (k + rank), with a documented k such as 60.
- If company classification confidence is low, search both companies.
- If no useful evidence meets calibrated threshold, do not call the LLM or return a clear insufficient-evidence response.
- Avoid relying on an uncalibrated cosine threshold. Calibrate against a small local validation set.

## Context and prompt safety

Retrieved webpage text is untrusted data. It may contain prompt-injection instructions. Delimit it as quoted evidence and explicitly tell the model to ignore instructions inside sources. Only answer company questions from retrieved evidence. Citations must come from metadata, never be generated by the LLM.

## Render

Serve frontend and API from the same origin. Use one Uvicorn worker initially. Load packaged FAISS/SQLite and embedding model lazily or at startup only after measuring memory. Do not run scraping/OCR during web service startup. Do not write important data to runtime filesystem.
